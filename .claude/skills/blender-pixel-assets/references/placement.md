# Placing assets in maps

Maps are generated by `tools/genmaps.cpp`; regenerate with `.\build.ps1 -Maps`
after `.\tools\make_manifest.ps1` (genmaps reads image sizes from the manifest).

## Which call

| Call | Draws | Use for |
| --- | --- | --- |
| `m.Prop("props", name, x, y)` | Standing on (x, y), sorted with the player by base | Furniture, anything with height |
| `m.Overlay("props", name, x, y)` | Centred on (x, y), on the floor under everyone | Rugs, **stairs**, stairwells |
| `m.Object(id, type, x, y)` + `o["sprite"]` | Standing, and interactable | Workbench, range, chest, sign, board |
| `PlaceBuilding(m, art, x, y, w, h, target, spawn, label, "props")` | Building with doorway collision and portal | Exteriors |
| `RoomShell(m, cols, rows, CELL, floor, wall, door_l, door_r)` | Floor, two-course back wall, sides, front with a doorway | Every interior |

**Stairs must be overlays.** A standing prop sorts by its base; a player
climbing a flight is north of that base the whole way, so they are drawn behind
the stairs they are on.

**Overlays and draw order.** The ground layer draws floor tiles first and
overlays (tile keys starting `~`) in a second pass. Before that pass existed, a
rug straddling a 256px chunk border had the next chunk's floor painted over its
right side. Do not work around it with naming alone.

## Collision

Block a band along the base of a prop, not its whole footprint, so the player
can walk behind its upper half:

```cpp
auto piece = [&](const string& art, int x, int y, int cw, int ch) {
    m.Prop("props", art, x, y);
    if (cw > 0) m.Collision(x - cw / 2, y - ch, cw, ch);
};
piece("wardrobe", 258, 246, 34, 14);
```

Width is the art's opaque width; measure it:

```
python -c "from PIL import Image; im=Image.open('assets/props/x.png').convert('RGBA'); a=im.getchannel('A').point(lambda v:255 if v>=250 else 0); print(im.size, a.getbbox())"
```

## Portals between floors

A second floor is its own map joined by step-through portals
(`requires_interact = false`). Two rules, both enforced by the self-test:

- Every portal's target spawn must exist in the target map.
- The arrival spawn's feet (16x10 box ending at the spawn point) must not
  overlap a step-through portal there, or the player bounces between floors.
  Arrive a tile clear of the stairs.

Keep the stairs in the same spot on both floors.

## Checking a layout

```
python .claude/skills/blender-pixel-assets/scripts/render_map.py maps/house_inn.mx out.png 2
```

Red = collision, blue = NPCs, green = portals. Look for: furniture over a
doorway path, props overlapping, a portal inside collision, empty regions. Add
any new interior id to the lists in `tools/selftest.cpp` (`kMaps`, the
reachability list, the leak list) so it is checked.

## Seeing it in-game

New games start on the overworld. To look at an interior directly, temporarily
change `world.LoadMap("overworld", "start", ctx)` in `Game::NewGame` to read an
env var, launch from the **Bash** tool (PowerShell-launched processes get no
window), and remove the hook before committing. If keys stop reaching the
window, the user is probably using the machine; fall back to `render_map.py`
rather than fighting for focus.
